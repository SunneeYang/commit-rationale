# 提交说明质量评测

用固定输入检查插件是否保留重要背景、避免无价值正文，并正确处理历史重组。案例均为合成数据，不包含真实项目代码或私有开发记录。

新增[单条提交正文的维护价值评测](handoffs.md)：让全新会话处理后续任务，对比同一提交保留／移除正文的结果。[Git 工作流评测](workflows.md)保留此前写作规则的对照；本页保留更早的封闭输入基础回归。三个问题分开报告，不混算为一个通过率。

## 案例与判断标准

| 案例 | 必须观察到的行为 |
| --- | --- |
| [仅有 diff](../plugins/commit-rationale/evals/01-title-only/prompt.md) | 只写准确标题，不编造动机或测试结果 |
| [低价值经过](../plugins/commit-rationale/evals/02-low-value-history/prompt.md) | 不把发现过程、讨论次数和耗时填进正文 |
| [外部约束](../plugins/commit-rationale/evals/03-external-constraint/prompt.md) | 保留十五分钟撤权期限及未来不能放宽的含义 |
| [普通 merge](../plugins/commit-rationale/evals/04-merge-context/prompt.md) | 将源提交的兼容性约束和验证边界提炼进新正文 |
| [squash](../plugins/commit-rationale/evals/05-squash-context/prompt.md) | 保留部署前提，丢弃已取消的分布式锁方案 |
| [amend](../plugins/commit-rationale/evals/06-amend-context/prompt.md) | 覆盖修订后的整体，保留旧约束，不扩大旧测试结论 |

每个案例旁的 `graders/criteria.md` 是公开的语义评分标准，不要求逐字匹配示例。两组使用相同输入和评分标准；是否调用技能本身不算质量得分。

## 基础回归对照

[2026-09-22 完整记录](codex-2026-09-22.json)：Codex CLI 0.155.1，模型请求使用 `gpt-6-astra`，推理强度为 `medium`。6 个案例每组每例运行一次，共得到 12 份有效输出。

| 条件 | 按公开标准通过的案例 |
| --- | --- |
| 不提供技能规则 | 6/6 |
| 直接提供完整 SKILL.md | 6/6 |

本次未观察到通过率提升。输入已经完整提供背景，案例数量少且每项只运行一次；这些结果适合检查基本行为，不支持稳定增益或生产效果的结论。

复查发现，这批输入已将约束整理成要点，merge 提示还明确指定了“首要阅读入口”；执行器禁止查仓库，评分对夹带 diff 复述也较宽松。因此 6/6 存在明显的天花板，不能代表真实提交工作流。后续增加[合成 Git 工作流评测](workflows.md)，保留本轮结果而不覆盖或重新解释旧分数。

## 对照方法

使用 [run_codex.py](run_codex.py) 调用 `codex exec`。两组都在新的临时只读会话中处理相同的合成输入；实验组通过 `developer_instructions` 额外收到完整 `SKILL.md`。这测的是规则文本的影响，不是原生插件的自动选择、加载或钩子效果。

为避免本机已安装技能污染基线，评测进程停用插件、个人记忆、宿主技能发现、技能搜索和 AGENTS.md 加载；连接设置与登录态保留。所有设置仅作用于子进程，不修改用户配置。共享指令要求只根据案例作答，不调用工具；执行日志中出现工具活动的样本会被拒绝评分。

2026-09-23 排查工作流评测时发现，旧执行器的 `mcp_servers={}` 不会清空继承的 MCP 配置。此处保留的 12 份基础样本均没有工具调用，但不能声称生成时 MCP 工具不可用。当前执行器已改为逐项禁用并在模拟请求中检查工具名称；该修复不追溯改变旧记录或分数。

正式生成前，用仅监听本机回环地址的模拟端点检查两组模型输入：基线不含技能规则，实验组包含完整规则，两组均不含读取钩子和 Ponytail 提示。模拟端点只验证输入，随后正式生成仍走用户已有的 Codex 连接。

每个案例交替安排两组先后顺序。生成完毕后打乱候选顺序、隐藏条件标签，由同型号 Codex 按公开标准集中评分；检查评审结果没有遗漏、重复或未知样本。评分模型与生成模型相同，不能当作独立人工评审。结果保留全部原始输出、评分理由、用例和技能哈希。

没有把“调用了技能”当作得分，也没有测试真实仓库历史检索、代码修改、插件自动触发率、速度或 token 节省。运行耗时及 token 使用仅作为审计信息保留。

## 复现

需要 Python 3.9+（仅标准库）、支持脚本所用配置项的 Codex CLI，以及可用的 Codex 登录态和模型连接。本次验证版本为 0.155.1；`skip_host_skill_discovery` 当前属于开发中功能，升级 CLI 后应重新确认隔离检查通过。

从仓库根目录运行：

```bash
python3 benchmarks/run_codex.py --self-test
python3 benchmarks/run_codex.py --output benchmarks/codex-new-run.json
```

脚本包含 12 次生成与 1 次集中评分，使用现有 Codex 额度，每次 CLI 调用最多等待 180 秒。结果逐次写入指定文件，已有结果不会被覆盖；异常中断保留已完成输出，未完成评分时 `scores` 为 `null`。它不会自动发布报告、提交文件或推送代码。

案例沿用原有 Markdown 输入与 rubric；Codex runner 提取正文，不使用其中为 Claude runner 设置的工具列表或回合数。
