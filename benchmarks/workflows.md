## 输入设计

| 场景 | Agent 实际拿到的输入 | 需要自行完成的工作 |
| --- | --- | --- |
| 对话中的背景裁决 | 暂存改动，加上混有草案、噪声和旧验证结果的对话记录 | 区分最终约定与已放弃方案，不扩大旧测试结论 |
| merge | 一个真实双亲 merge，用户只要求拟说明 | 找到本次引入范围，读取源正文，排除目标分支已有的无关背景 |
| amend | 原提交有正文，工作区有暂存补改 | 阅读原说明和最终整体，保留兼容约束 |
| 历史读取 | 请求评估两秒超时能否改为八秒，期限只存在于旧提交正文 | 查回历史依据，并核实其是否仍适用 |
| 文档负对照 | 代码与本次文档 diff 已完整解释约束 | 不重复已有说明，不为了有正文而填充 |
| squash | 分支历史包含后来取消的方案和最终部署前提 | 根据最终树重写，丢弃已过时信息 |

提示不再告诉 Agent “这些是重要约束”“最终正文必须保留什么”，也不将源正文直接贴给 merge、amend、squash 或历史读取场景。背景裁决场景提供的是混合对话记录，而非预先筛好的结论。用例仍是小型合成仓库，并非生产项目或完整长会话的替代。

## 控制与评分

- 两组从内容、引用、HEAD 和暂存区均一致的仓库副本开始。生成后再次检查仓库快照，确认没有写入。
- 允许只读 shell 工具与计划更新，保存查询命令；不将“用了更多命令”或“调用了技能”当作得分。其他工具活动拒绝评分。
- 5 个写作场景的实验组显式收到完整 `SKILL.md`；历史读取场景仅收到读取提醒，因为写作技能不应覆盖单纯的代码评估。
- 原生插件、个人记忆及其他技能的自动发现保持关闭，逐项禁用继承的 MCP 服务器并关闭网页搜索；CLI 配置检查确认服务器全部禁用。本机模拟端点验证有／无规则的隔离。因此本轮仍不测自动触发率。
- 标准在生成前固定，oracle 和评分项只交给评审，不放入被测仓库或生成请求。按背景保留、事实准确、冗余控制、验证边界分别报告，不只给一个总通过率。
- 样本打乱顺序并隐藏组别，由同型号模型逐项评分。原始输出和理由公开供复核；这不是独立人工评审。
- 每组每例只运行一次。保留全部结果及基础测试，不以出现分差为停止条件，也不在看过结果后修改评分标准。

## 复现

[仓库构造、输入和评分标准](workflow_cases.py) · [执行器](run_workflows.py)

```bash
python3 -B benchmarks/run_workflows.py --self-test
python3 -B benchmarks/run_workflows.py --output benchmarks/workflows-new-run.json
```

中止后可以复用已经完成的样本，写入新文件：

```bash
python3 -B benchmarks/run_workflows.py --resume benchmarks/workflows-interrupted.json --output benchmarks/workflows-resumed-new.json
```

续跑会核对执行协议、CLI、模型、推理强度、源码基线、技能、提醒、用例和评分标准，并重建仓库验证每份快照。原文件不覆盖，已完成样本不重新生成。续跑文件记录来源哈希及执行器哈希；修改工具隔离条件后必须完整重跑，不能复用旧协议样本。

使用与基础评测相同的 Codex 模型和推理强度。仓库在临时目录中由 Git 构造，不读取真实项目；Agent 在只读沙箱中生成草稿或评估，不执行真实合并、amend 或代码修改。不要把此次读取评估结果等同于实际修改后的正确性或线上收益。

[首次逐项禁用尝试](workflows-2026-09-23-v2.json)因 CLI 配置键的引号处理错误，在本机隔离探针阶段即中止，没有模型生成样本。修正后先通过配置检查，再重新执行全部两组案例；用例、评分标准、技能、提醒和模型均未改变，旧输出不混入新一轮分数。
